Attack the audit log, then audit it
The same decisions are written to three ledgers. Rewrite one as a root attacker would, then run the independent watcher.

    

      

        
R1 · plain table
Trusts the host.
Rows sit in a database on the gateway machine. Anyone with root can edit or delete them, and nothing notices.

        
R2 · local hash chain
Catches edits, not rewrites.
Each row commits to the one before it. But an attacker can recompute the whole chain after editing it, or cut off the newest rows.

        
R3 · Merkle root on-chain
Proves it from outside.
Every few rows, a 32-byte Merkle root goes to AuditAnchor.sol, a write-once contract off the host. A rewrite no longer matches it.
